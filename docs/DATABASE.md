# BookYourBarber — Database Architecture & Schema Reference

## 1. Overview & Invariants

The database layer is hosted on PostgreSQL (via Supabase) and managed through version-controlled migrations in `supabase/migrations/`.

- **Primary Keys**: All tables use `UUID` primary keys generated by `gen_random_uuid()` (or `uuid_generate_v4()`).
- **Timestamps**: All mutable tables contain `created_at` and `updated_at` timestamps with an automatic PostgreSQL trigger `update_updated_at_column()`.
- **Tenant Isolation**: All tenant-owned tables contain a `tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE`.
- **Row Level Security**: RLS is explicitly enabled on all 24 tables.

## 3. Indexes

Performance-critical paths are indexed:
- `idx_tenant_memberships_tenant` on `tenant_memberships(tenant_id)`
- `idx_tenant_memberships_user` on `tenant_memberships(user_id)`
- `idx_appointments_tenant` on `appointments(tenant_id)`
- `idx_appointments_reference` on `appointments(booking_reference)` (UNIQUE)
- `idx_appointments_date` on `appointments(tenant_id, appointment_date)`
- `idx_customers_phone` on `customers(tenant_id, phone)`
- `idx_payments_appointment` on `payments(appointment_id)`
- `idx_refunds_reference` on `refunds(refund_reference)` (UNIQUE)

## 4. Concurrency & Overlap Exclusion Constraints

To prevent concurrent double-booking and overlapping appointments for the same barber:
- **Extension**: `btree_gist` enabled to combine scalar equality (`tenant_id`, `staff_id`) with range overlap.
- **Generated Column**: `appointments.appointment_range tsrange GENERATED ALWAYS AS (tsrange((appointment_date + start_time), (appointment_date + start_time + (duration_minutes * INTERVAL '1 minute')), '[)')) STORED`.
- **Exclusion Constraint**:
  ```sql
  ALTER TABLE appointments ADD CONSTRAINT exclude_overlapping_staff_appointments
    EXCLUDE USING gist (
      tenant_id WITH =,
      staff_id WITH =,
      appointment_range WITH &&
    )
    WHERE (status NOT IN ('cancelled') AND staff_id IS NOT NULL);
  ```
- **Interval Overlap Guarantee**: Guarantees that any overlapping interval (e.g. 09:00–10:00 and 09:30–10:00) will be aborted by the PostgreSQL database engine.

## 5. Row Level Security (RLS) Policies

All policies are declared in `supabase/migrations/20260909000002_rls_policies.sql` and hardened in `supabase/migrations/20260911000001_pre_supabase_hardening.sql`.

Helper functions with `SECURITY DEFINER`:
- `is_tenant_member(lookup_tenant_id UUID)`: verifies user is in `tenant_memberships`.
- `get_tenant_role(lookup_tenant_id UUID)`: returns `'OWNER'` or `'MANAGER'`.
- `is_platform_admin()`: verifies user is registered in `platform_admins`.

Default rule: **Closed by default**. Cross-tenant access is rejected at database execution time. Guest booking lookup is secured via `lookup_guest_appointment` RPC with verification rather than broad anonymous SELECT.
